# Test vectors

Known-answer vectors for every Lume Cloud client. An implementation (Swift
`Kit/`, Kotlin LumeAndroid) is conformant when it reproduces every value here.
`PROTOCOL.md` is normative; these files pin it down byte for byte.

## `crypto.json`

Generated by the Swift Kit (`Kit/Tests/LumeCloudKitTests/CryptoVectorTests.swift`)
and re-verified by the same test on every `swift test`, so the file and the
Kit can't drift apart. To regenerate after an intentional change:

```bash
cd Kit && LUME_CLOUD_WRITE_VECTORS=1 swift test --filter CryptoVectorTests
```

Every binary value is **base64url without padding** unless its field name ends
in `Hex`. Fixed inputs: the root key is the bytes `0x00…0x1f`, the account id
is base64url of `0x00…0x0f`, and the nonces are `0xa0…0xab` and `0xb0…0xbb`.

| Field | What to check |
|---|---|
| `keys.encKey` / `idKey` / `authKey` | `HKDF-SHA256(IKM = rootKey, salt = empty, info, L = 32)` with each entry's `info` (§2.1). |
| `keys.authVerifier` | `base64url(SHA-256(authKey))` (§2.2). |
| `keys.authToken`, `keys.authorizationHeader` | `base64url(authKey)` and `Bearer <accountId>.<authToken>` (§2.2). |
| `records[].rid` | `base64url(HMAC-SHA256(idKey, UTF8(logicalKey)))` (§2.3). |
| `records[].canonicalPayload` | The exact plaintext bytes. Parse `payload` (or `canonicalPayload`), re-serialize canonically, and compare strings. |
| `records[].envelope` | `base64url(0x01 ‖ nonce ‖ AES-256-GCM ciphertext ‖ tag)` with key `encKey`, nonce `nonceHex`, AAD `UTF8(rid)` (§2.4). Seal with the given nonce and compare, and open it back to `canonicalPayload`. |
| `unsupportedEnvelope` | Version byte `0x02`: opening must report "unsupported version". The client skips and keeps such a record and never overwrites or deletes it. |
| `recoveryKey.rendering` | The recovery key for `rootKey`. Every entry of `acceptedVariants` must decode to `rootKey`, and every entry of `rejectedTypos` must fail the checksum. |
| `pairing` | HPKE base mode (RFC 9180), DHKEM(X25519, HKDF-SHA256) / HKDF-SHA256 / AES-256-GCM, `info = UTF8(pairing.info)`, `aad = UTF8(pairing.code)` (§4.5). Open `enc` + `ciphertext` with `recipientPrivateKey` (raw X25519 scalar) and compare with `canonicalGrant`. Opening with any other code must fail. |

The HPKE ciphertext was sealed once with a random ephemeral key, because
CryptoKit doesn't let callers pick it. Verify it by **opening**; an
implementation can't reproduce it by sealing. The generator keeps the committed
ciphertext as long as it still opens.

### Canonical JSON

The payload plaintext (§2.5) and the pairing grant are **RFC 8785 (JCS)** JSON:

- object keys sorted at every level by **UTF-16 code units** (JavaScript's
  default sort, Kotlin's `String.compareTo`);
- no whitespace;
- strings escaped like `JSON.stringify`: `\"`, `\\`, `\b`, `\f`, `\n`, `\r`,
  `\t`, other control characters as lowercase `\u00xx`, and everything else
  (including `/` and non-ASCII) as literal UTF-8;
- numbers formatted like ECMAScript `Number.prototype.toString`: integers
  without a fraction (`1`, never `1.0`), `1234.5`, `0.00001`, `1e-7`, `1e+21`.

The second record's `futureField` exercises the escaping and number corner
cases. The pretty-printed `payload` objects are for reading only; the
`canonicalPayload` strings are normative.

### Recovery key

The 256 key bits, big-endian, are packed into 52 Crockford base32 symbols
(`0123456789ABCDEFGHJKMNPQRSTVWXYZ`); the last symbol carries one key bit and
four zero bits. Then comes one check symbol: the 52-digit base-32 number mod 37,
written with the same alphabet for 0…31 and `*`, `~`, `$`, `=`, `U` for 32…36.
The 53 symbols are grouped by four with `-`, so the check symbol stands alone at
the end. Decoding is case-insensitive, maps `I`/`L` → `1` and `O` → `0`, ignores
`-` and whitespace, and rejects non-zero padding bits.
